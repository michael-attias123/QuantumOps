# P1 — L0 contract + local runtime: overview

**Status:** ✅ done · **Commit:** `1c8567c` · **CI:** [run #2](https://github.com/michael-attias123/QuantumOps/actions/runs/41998175457) green
(lint & test and pin matrix on amd64 + arm64, secret scan) · **Cost:** $0

## Goal
Researchers write plain Qiskit, and the full CPU → QPU → post-processing loop runs **in one process on any laptop**,
with no cluster. This fixes the contract between researcher code and the platform before any Kubernetes work.

## What was built

### 1. The researcher contract (L0)
An algorithm is a folder with two files and nothing platform-specific:

```
algorithms/vqe_h2/
├── algorithm.py     # class Algorithm(config): pure Qiskit, no qops_* imports
└── algorithm.yaml   # kind: variational, default config
```

The `kind` decides which methods the class must have:

| kind | required | optional |
|---|---|---|
| `sampling` | `circuits()` | `analyze(distributions)` |
| `variational` | `ansatz()`, `hamiltonian()`, `initial_point()` | `exact_value()` |
| `qec-memory` | `code()` | — (runs from P10) |

The loader checks this up front and gives a clear error ("kind 'variational' requires method(s): ansatz, …").
A CI test keeps `algorithms/` free of platform imports.

### 2. Two working algorithms
| Algorithm | Result (local, noiseless) |
|---|---|
| `ghz_benchmark` (3 qubits by default) | fidelity **1.0** (from Z-basis population + X-basis parity) |
| `vqe_h2` (H2 molecule, 2 qubits) | energy within **~1e-6 Ha** of exact; target was 1.6e-3 Ha (chemical accuracy) |

### 3. Platform packages
| Package | What it now does |
|---|---|
| `qops-core` | contract loader, provider-neutral results (`CircuitResult` = probabilities, plus counts/shots), `RunState` snapshots (`state.json` with `schema_version`, atomic writes), QPY circuit helpers |
| `qops-providers` | the provider interface every QPU/GPU provider will implement (`submit`/`status`/`result`/`cancel`/`estimate_cost`, capability flags), an entry-point registry, and a synchronous **Aer** provider (`exact` = exact probabilities, `sampler` = seeded shots) |
| `qops-stages` | **SPSA** optimizer in ask/tell form whose entire state, random generator included, is JSON; Pauli **measurement grouping** and energy from measured distributions |
| `qops-runtime` | the in-process loop: ask (L1) → run circuits (L2) → tell (L3), saving `state.json` **after every iteration** |
| `qops-cli` | `qops run --local`, `qops run --resume`, `qops new algorithm` |

### 4. State hydration, proven locally
Because the optimizer's entire state is saved, a run can stop at any iteration and resume in a new process with an
**identical** result. A test checks this: a run stopped after 13 iterations and resumed gives exactly the same history
and final energy as an uninterrupted run. This is the property the cluster phases depend on, where each iteration
happens in a different pod.

### 5. Version pin matrix
Qiskit **2.6.1** resolves together with everything later phases need: mthree 3.0, mitiq 1.1, qiskit-ibm-runtime 0.51,
qiskit-ionq 1.1 and qiskit-braket-provider 0.27. All of them have **arm64** wheels for the Oracle cluster. They're
locked as a `compat` group and tested by a new CI job on both architectures. Details: [compat-matrix.md](../compat-matrix.md).

## How to use it
```bash
uv run qops run --local algorithms/ghz_benchmark
uv run qops run --local algorithms/vqe_h2                      # ~0.7 s
uv run qops run --local algorithms/vqe_h2 --shots 4000         # shot-based instead of exact
uv run qops run --local algorithms/ghz_benchmark --set num_qubits=5
uv run qops run --local algorithms/vqe_h2 --max-steps 20       # stop early ...
uv run qops run --resume .qops/runs/vqe_h2/state.json          # ... resume, same trajectory
uv run qops new algorithm my_algo --kind variational           # scaffold a valid algorithm
make verify-p1                                                 # all P1 checks
```

## Decisions made along the way
- **Results are probabilities.** Exact simulators return exact distributions, and shot-based backends return counts that
  are normalized. Algorithms always receive the same shape (`list[dict[str, float]]`).
- **Config goes to `__init__`**, so the signature is `circuits()`, not `circuits(config)`. The architecture doc is updated.
- **`real_amplitudes` (6 parameters) for H2** instead of `efficient_su2`. The ground state is real, so fewer parameters
  converge faster.
- **Line length is left to the formatter** (ruff E501 off). Qiskit has no type hints, so mypy treats it as untyped.

## Issues found and fixed
- `qops run --set novalue` crashed with a traceback. It now prints a clear error and exits with code 2, and a test covers it.
- The CLI scaffold test wrote state into the repo's `.qops/`; it now uses a temp directory.

## Known limitations (carried forward)
- **SPSA needs ~100–150 iterations** for H2 and is far off at 20–40. That's fine locally but too many for IBM's
  10 free minutes a month, so **P8 must tune for small budgets** before using real hardware.
- Only the local Aer provider exists. Real providers (IBM, IonQ, Braket) arrive in P7.
- `qec-memory` is defined but raises "runs from P10".
